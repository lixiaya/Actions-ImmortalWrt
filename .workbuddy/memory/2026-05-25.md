## 项目熟悉 + 修复编译报错

### 项目概况
- ImmortalWrt GitHub Actions 自动编译项目
- 目标设备：Cudy TR3000 256MB v1（mediatek/filogic 平台，aarch64_cortex-a53）
- 内核版本：Linux 6.12
- 已启用：BTF、daed、luci-app-daed、apk-openssl、kmod-sched-bpf

### 修复内容（v1 - 第一次提交 9e6f19b）
**根本错误**：`.github/workflows/build.yml` 中直接跑 `make package/kernel/mac80211/compile`，但此时 host 工具链（`staging_dir/host/bin/libdeflate-gzip` 等）尚未构建，导致解压失败报错。

**修复方案**：
- 删除 `预编译 mac80211` 步骤
- 在主编译前添加 `make tools/install && make toolchain/install`
- 两个 job（build 和 build-ssh）均已修复

### 修复内容（v2 - 第二次提交 9e3d00b）
**第二次报错**：`package/kernel/mt76` 编译失败，缺少 `mac80211-backport/backport/autoconf.h`。
**原因**：单独 `make tools/install && make toolchain/install` 后，mac80211 在编译时使用 `allnoconfig`（最小配置），导致 mt76 依赖的 backport 头文件未生成。
**最终修复**：
- 删除手动工具链构建步骤，改用 `make download -j$(nproc)` 预下载
- 让 `make`（即 `make world`）全权按正确依赖顺序编译：tools → toolchain → kernel → mac80211 → mt76 → packages
- 核心原则：不要手动干预 OpenWrt 的编译依赖链
